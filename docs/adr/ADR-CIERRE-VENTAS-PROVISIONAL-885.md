# ADR-CIERRE-VENTAS-PROVISIONAL-885 (aprobación PO en conversación; validación pendiente)
## Decisión
Caja/stock se consolidan una vez, si pasan sus controles actuales. Solo las discrepancias comerciales de reversas/notas pueden quedar pendientes. No se difieren cobros inconciliables, errores de lectura, unidades aproximadas no nulas ni precio desconocido de entrega vigente. Confirmación explícita ligada a huella del subtotal y casos; requiere arqueo declarado. No modifica #306: el día tiene cierre operativo, no se salta.
## Contrato
El snapshot original guarda `ventasEstado: PROVISIONAL`, `ventasProvisional`, subtotal identificado y casos. `CierreDia.totalVentas` conserva el subtotal original por compatibilidad; NO es venta neta certificada. La lectura complementaria `regularizacionVentas` conserva las revisiones y devuelve `ventasTotalCertificado`/totalCertificado null hasta resolver todos los casos. Se debe mostrar la etiqueta provisional en consumidores financieros, nunca sumar el subtotal como definitivo. El comprobante imprimible se rotula provisional o regularizado; no se reabre ni se reescribe la caja.
ADMIN puede registrar el descuento omitido, o cero con evidencia de que no corresponde descuento. No deriva de pagos/NC. Cada revisión incluye referencia, actor y fecha; retirada append-only vuelve a dejar pendiente. No hay ajuste automático ni modificación retroactiva de stocks. Si nunca se recupera evidencia, sigue pendiente sin bloquear nuevas cajas. El monto declarado es un ajuste comercial del día del cierre original, no dinero ni una venta nueva de la fecha de regularización.
## Gates
Pruebas de autorización, huella stale, conteo obligatorio, bloqueo de cobros y precios, cierres consecutivos, regularización/retiro/duplicados y UI. Verificar todos los consumidores de totalVentas original (incluidas integraciones externas), retención de Historial, permisos, reportes de ventas #747 y revisión visual antes de liberar. El registro de referencia es declaración administrativa, no certificado externo.

### Dependencia entre regularizaciones
Un ajuste cero exige un fundamento estructurado: ninguna venta reconocida, nota sin efecto en ventas, o ajuste ya registrado para el mismo pedido. En este último caso el servidor comprueba el descuento positivo; impide retirarlo hasta que se retiren los ceros dependientes. Se conserva el motivo, con referencia. La operación es serializable y no altera snapshots.
